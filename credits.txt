## 1. Project code and original work

GardenTwin is an original project developed by its team. The team designed and implemented the garden simulation backend, crop profiles, soil and nutrient calculations, API endpoints, intervention comparisons, and integration pipelines.

**Project repository:**  
https://github.com/Tsunami-The-Coder/tbd

The following components were implemented as part of GardenTwin:

- Daily garden simulation engine
- Crop growth and thermal-time calculations
- Seven crop profiles: tomato, pepper, cucumber, lettuce, carrot, bean, and strawberry
- Soil-water simulation
- Nutrient balance and leaching calculations
- Illustrative crop nutrient-demand calculations
- Irrigation intervention comparisons
- Historical weather ingestion and fallback handling
- Soil data ingestion
- Satellite imagery processing and pretrained-model integration
- AI analysis pipeline and API endpoints
- Automated tests and validation infrastructure

The GardenTwin team is responsible for its own implementation and for the project-specific assumptions and integration logic described in this document.

No third-party source-code repository has been confirmed as the source of copied GardenTwin application code. The external frameworks, models, and datasets listed below are credited separately.

## 2. Weather and climate data

### NASA POWER

**Provider:** NASA Langley Research Center  
**Resource:** Prediction of Worldwide Energy Resources (POWER)  
**Official documentation:** https://power.larc.nasa.gov/docs/  
**Daily API documentation:** https://power.larc.nasa.gov/docs/services/api/temporal/daily/  
**API overview:** https://power.larc.nasa.gov/docs/services/api/

**How GardenTwin uses it:**

NASA POWER is the primary source for historical daily weather and climate information used by the garden simulation. The backend retrieves regional meteorological and solar variables for the garden's location and simulation dates.

This information contributes to the environmental conditions used by the crop-growth and soil-water calculations.

### Open-Meteo

**Provider:** Open-Meteo  
**Official website:** https://open-meteo.com/  
**Historical Weather API:** https://open-meteo.com/en/docs/historical-weather-api  
**Forecast API:** https://open-meteo.com/en/docs  
**Historical Forecast API:** https://open-meteo.com/en/docs/historical-forecast-api  
**API source code:** https://github.com/open-meteo/open-meteo

**How GardenTwin uses it:**

Open-Meteo provides supplementary weather information when NASA POWER data is missing required variables. It is also used to retrieve short-range weather forecasts for the forecast and intervention workflow.

The forecast data helps GardenTwin evaluate how upcoming environmental conditions could affect the modeled garden.

Open-Meteo's API specification identifies the historical weather API as using ERA5 and ERA5-Land reanalysis products. Its API specification also identifies a CC BY 4.0 license for the historical-weather API description. Data and service terms should be checked for the particular endpoint being used.

### ECMWF ERA5

**Provider:** European Centre for Medium-Range Weather Forecasts (ECMWF) and Copernicus Climate Change Service  
**Official ERA5 information:** https://www.ecmwf.int/en/forecasts/datasets/complete-era5-global-atmospheric-reanalysis  
**ERA5 documentation:** https://confluence.ecmwf.int/pages/viewpage.action?pageId=216494465  
**Climate Data Store:** https://cds.climate.copernicus.eu/

**How GardenTwin uses it:**

ERA5 is the historical weather dataset associated with the saved Microsoft Aurora inference artifact.

The Aurora artifact was generated using historical ERA5 data from June 15, 2022. It is a cached historical model result, not a live weather prediction for the GardenTwin simulation period.

ERA5 is therefore credited as an underlying dataset used by the model artifact, not as the primary live weather feed for GardenTwin.

### NOAA Global Forecast System (GFS)

**Provider:** National Oceanic and Atmospheric Administration (NOAA)  
**Official GFS information:** https://www.ncei.noaa.gov/products/weather-climate-models/global-forecast  
**NCEP model information:** https://www.nco.ncep.noaa.gov/pmb/products/gfs/

**How GardenTwin uses it:**

GFS weather data was used as the input source for a saved NVIDIA FourCastNet1 inference artifact through NVIDIA Earth2Studio.

The saved artifact was initialized on November 15, 2026 at 00:00 UTC and had a valid time of 06:00 UTC. This artifact is historical relative to later simulation dates and should not be represented as a current or continuously updated forecast.

## 3. Soil data

### USDA NRCS SSURGO

**Provider:** United States Department of Agriculture (USDA), Natural Resources Conservation Service (NRCS)  
**SSURGO Portal:** https://www.nrcs.usda.gov/resources/data-and-reports/ssurgo-portal  
**Web Soil Survey:** https://websoilsurvey.nrcs.usda.gov/  
**Soil Data Access:** https://sdmdataaccess.nrcs.usda.gov/

**How GardenTwin uses it:**

GardenTwin retrieves soil-survey information for the selected garden location using USDA SSURGO data.

The soil information provides a real-world geographic soil-data foundation for the simulation, rather than relying entirely on manually invented soil characteristics.

**Important limitation:** SSURGO map-unit information is not equivalent to a laboratory soil test from the user's individual garden. GardenTwin does not currently have verified measurements of the garden's actual available nitrogen, phosphorus, or potassium. Nutrient availability and fertilizer recommendations must therefore remain unknown unless appropriate soil-test information is supplied.

**How GardenTwin uses it:**

GardenTwin downloaded and processed NASA HLS satellite imagery for the Prithvi-EO-2.0 pipeline.

The available imagery observations used in the project include:

- June 2, 2025
- June 25, 2025
- July 25, 2025
- August 29, 2025

**Important limitation:** The current Prithvi integration performs pretrained feature extraction. It does not constitute a trained GardenTwin crop-disease classifier or a validated crop-health prediction system.

## 7. GardenTwin's own simulation methods and assumptions

The following are project-specific implementations and assumptions. They are not pretrained external models.

### Thermal-time and growing-degree-day calculations

GardenTwin uses temperature-based thermal-time calculations to estimate crop development.

The project calculates daily growing-degree-day contributions and accumulates them to represent crop development over time.

This is a common agricultural modeling concept, implemented within GardenTwin's own crop simulation code.

### Crop profiles and growth calculations

GardenTwin contains seven crop profiles:

1. Tomato
2. Pepper
3. Cucumber
4. Lettuce
5. Carrot
6. Bean
7. Strawberry

Each profile contains crop-specific parameters such as temperature thresholds, development-stage thresholds, maximum height, and biomass-related parameters.

The profiles are project-specific approximations. The additional crop profiles use a generalized growth framework and have not been calibrated against independent field measurements.

### Soil-water simulation and irrigation comparisons

GardenTwin implements its own soil-water simulation and irrigation intervention logic.

It uses weather conditions and modeled soil-water state to estimate whether irrigation may be useful and to compare alternative irrigation interventions.

These calculations are part of GardenTwin's original backend implementation.

### Nutrient balance, leaching, and nutrient demand

GardenTwin implements its own nutrient-balance and leaching calculations.

The current generic illustrative nutrient-uptake assumptions are:

- Nitrogen: 0.030 × daily biomass gain
- Phosphorus: 0.005 × daily biomass gain
- Potassium: 0.035 × daily biomass gain

These are internal illustrative assumptions, not experimentally calibrated GardenTwin coefficients, verified fertilizer application rates, or a substitute for a soil test.

GardenTwin does not currently calculate validated fertilizer product dosages.

### Intervention and recommendation logic

GardenTwin combines simulation state and available environmental information to support decisions about watering and garden management.

The recommendation and intervention logic is implemented by the GardenTwin team. It should not be mistaken for a direct output from any of the pretrained foundation models listed above.
